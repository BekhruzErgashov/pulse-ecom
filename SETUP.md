# Настройка проекта — с чего начать

Это чек-лист для того, кто впервые открывает проект (человек или другой
Claude-чат). Если вы — Claude и читаете этот файл: расскажите человеку,
что из списка ниже обязательно, что нет, и помогите пройти по шагам —
спросите, что из сервисов ему нужно, и дальше идите по соответствующему
разделу.

Подробное описание архитектуры, всех фич и истории решений — в
`HANDOFF.md` (большой файл, читать по разделам через поиск, не целиком).

## 1. Запуск без единой настройки (для проверки, что всё открывается)

```bash
npm install
npm run dev
```

Откройте `http://localhost:3000`. Без единой переменной окружения
приложение уже работает — данные хранятся в памяти процесса (сбрасываются
при перезапуске сервера). Демо-аккаунты уже в списке разрешённых:

| Email | Пароль | Роль |
|---|---|---|
| anna@team.dev | demo1234 | admin |
| ivan@team.dev | demo1234 | member |
| olga@team.dev | demo1234 | member |

Этого шага достаточно, чтобы посмотреть интерфейс и мини-игры. Дальше —
только если нужно постоянное хранилище данных и/или интеграции.

## 2. Обязательно для прода (постоянное хранение данных)

Без этого блока данные живут только в памяти и стираются при каждом
перезапуске — не годится для реальной команды.

Скопируйте `.env.example` в `.env.local` и заполните:

- **`DATABASE_URL`** — строка подключения к Postgres. Проще всего —
  бесплатный проект на [Supabase](https://supabase.com) (Settings →
  Database → Connection string, **режим Transaction pooler**, не
  Session — важно для serverless). Neon и Railway тоже подходят.
- **`SESSION_SECRET`** — любая длинная случайная строка, подписывает
  сессионные куки. Сгенерировать: `openssl rand -hex 32`. Без неё сессии
  подписываются предсказуемым dev-ключом — небезопасно для прода.

Затем один раз:

```bash
npm run db:migrate
```

Прогонять `db:migrate` заново нужно после **любого** обновления
`lib/schema.sql.ts` (новые таблицы/колонки) — если что-то в приложении
падает с ошибкой про отсутствующую таблицу/колонку, скорее всего дело в
этом.

## 3. Опционально — Telegram-бот (уведомления и команды в Telegram)

Без этого блока приложение работает полностью, просто не будет
уведомлений в Telegram и кнопки «Привязать Telegram» в шапке не будет
работать.

1. Написать [@BotFather](https://t.me/BotFather) в Telegram → `/newbot`
   → получить токен.
2. В `.env.local` (и в Vercel → Environment Variables на проде) задать:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather.
   - `TELEGRAM_BOT_USERNAME` — username бота без `@`.
   - `TELEGRAM_WEBHOOK_SECRET` — любая случайная строка (сверяется с
     заголовком, который присылает Telegram, — защита от подделки
     вебхука).
   - `APP_URL` — публичный HTTPS-адрес приложения (на Vercel можно не
     задавать, используется `VERCEL_URL` автоматически).
   - `CRON_SECRET` — любая случайная строка, защищает cron-роут
     ежедневного дайджеста.
3. После деплоя (или после смены любой из переменных выше) один раз
   выполнить:
   ```bash
   npm run telegram:webhook
   ```
   Это регистрирует и вебхук, и список команд бота (`/mytasks`,
   `/today`, `/questions`, `/help`) в Telegram.

## 4. Опционально — Google Calendar (виджет «Сегодня» на доске)

Без этих переменных виджет просто показывает заглушку «не настроен» —
остальное приложение работает как обычно.

Подробная пошаговая инструкция (создание OAuth-клиента, scope,
redirect URI) — в `HANDOFF.md`, раздел «Google Calendar». Коротко:
Google Cloud Console → включить Calendar API → OAuth consent screen →
OAuth client ID (Web application) → redirect URI
`<APP_URL>/api/google-calendar/callback` → `GOOGLE_CLIENT_ID` и
`GOOGLE_CLIENT_SECRET` в `.env.local`/Vercel.

## 5. Деплой (Vercel)

```bash
npx vercel --prod
```

Все переменные из разделов 2–4, которые нужны, добавляются в
**Vercel → Settings → Environment Variables** (для Production и Preview),
после чего — Redeploy, чтобы они подхватились.

## Что уже не нужно настраивать

Мини-игры (`/w/<id>/game`) используют собственные картиночные ассеты —
уже лежат в `public/game/`, ничего дополнительно готовить не нужно.
Исходные большие ассет-листы, из которых эти картинки были вырезаны
(нарезка стен/пола/оружия/врагов), в архив не включены — они не нужны
для работы приложения, а весят десятки мегабайт; итоговые файлы уже
внутри `public/game/shooter/`.

## Проверка, что всё собирается

```bash
npm run typecheck   # tsc --noEmit, должно быть чисто
npm run lint        # eslint, должно быть чисто
npm run build        # полная сборка
```

## Если что-то не работает

Смотрите `HANDOFF.md` — там для каждой фичи расписана не только текущая
реализация, но и история проблем/исправлений (полезно, если поведение
кажется странным — возможно, это уже когда-то чинили и решение
задокументировано). Раздел «Ограничения / чего нет» там же — список
того, что сознательно не сделано.
