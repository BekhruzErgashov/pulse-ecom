# Пульс — трекер задач для команды

Next.js 16 + Tailwind v4. Доски задач с визуализацией этапов, защищённая
авторизация по приглашениям, админ-панель и приватные вопросы.

## Возможности

### Авторизация и доступы
- Вход по **email + паролю** (bcrypt-хэш, без открытого текста).
- Сессия — подписанная HMAC-кукой (httpOnly), подделать нельзя.
- **Регистрация только по списку разрешённых email** — попытка
  зарегистрироваться с email не из списка отклоняется.
- Первый когда-либо зарегистрированный пользователь автоматически
  становится администратором.

### Админ-панель (`/admin`, только для роли admin)
- Управление списком разрешённых email (выдать / отозвать доступ).
- Список всех участников: смена роли admin ↔ member, блокировка/разблокировка
  аккаунта. Нельзя разжаловать или заблокировать последнего администратора.

### Доски задач
- Канбан с 4 этапами, drag-and-drop, приоритеты, исполнители, сроки.
- "Рельс этапов" — визуализация количества задач по стадиям и % готовности.

### Пространства (workspaces)
- Отдельные команды/проекты изолированы друг от друга: пространство —
  контейнер для своих досок. Люди видят только те пространства, куда их
  добавили (или всё — если админ).
- Создание пространств — только для администратора (`/admin` → «Пространства»).
- В шапке сайта — переключатель пространства, если их несколько.

### Расширенная админ-панель
- **Пространства**: создание, список участников каждого, выдача/отзыв
  доступа конкретному аккаунту к конкретному пространству.
- **Сброс пароля**: администратор может сгенерировать новый пароль для
  любого аккаунта одной кнопкой (показывается один раз, для передачи
  человеку).
- Навигация (Задачи / Вопросы / Админ) сделана крупнее — сегментированные
  вкладки в шапке вместо мелких ссылок.

### Управление аккаунтами
- Пользователь может сам сменить пароль (шапка сайта → меню профиля →
  «Сменить пароль», требует знания текущего пароля).
- Администратор может **удалить аккаунт** целиком (не только заблокировать).
  Нельзя удалить себя или последнего администратора; если у пользователя
  есть свои пространства/доски — сначала нужно передать владение.
- После сброса пароля администратором пользователь получает временный
  пароль, но может сразу сменить его на свой через «Сменить пароль».

### Приглашения в пространство по разрешённым email
- В админ-панели, управляя участниками пространства, теперь выбираете из
  списка **разрешённых** email — включая тех, кто ещё не зарегистрировался.
- Если человек ещё не зарегистрирован — попадает в «Ждёт регистрации» и
  автоматически становится участником пространства сразу после регистрации.

### Исправлено: переключение пространств
- Переключение пространства через выпадающий список теперь гарантированно
  обновляет данные (раньше при быстром клике оставались задачи старого
  пространства).
- Выбор пространства запоминается (cookie) и не сбрасывается при переходе
  на вкладку «Вопросы» и обратно на «Задачи».

### Приватность между пространствами (исправлено)
- **Вопросы теперь тоже принадлежат конкретному пространству**, как и доски
  с задачами — раньше получателем вопроса можно было выбрать любого
  зарегистрированного пользователя системы, независимо от команды. Сервер
  теперь проверяет: получатель обязан быть участником того же пространства.
- Показывать/скрывать пароль — во всех полях ввода пароля (вход,
  регистрация, смена пароля) теперь есть кнопка-глаз.

### Исправлено окончательно: изоляция между пространствами
Раньше пространство передавалось как `?ws=...` — Next.js в некоторых
случаях не обновлял данные при смене только query-параметра (известная
особенность кэша роутера), из-за чего после переключения оставались
задачи старого пространства. Теперь пространство — часть самого пути
(`/w/<id>/boards`, `/w/<id>/questions`), а не параметр запроса: для
Next.js это гарантированно разные страницы, кэш не может их перепутать.
Старые ссылки `/boards` и `/questions` работают как раньше — редиректят
на актуальное пространство.

Пользователи, которых можно назначить исполнителем задачи или указать
получателем вопроса, — всегда только участники **текущего** пространства,
а не все зарегистрированные в системе.

### Видимость задач: все видят всё + личный фильтр
Как устроено в Trello, Jira, Linear и Asana: по умолчанию все, у кого есть
доступ к доске, видят **все** задачи — это стандарт для командной работы,
чтобы видеть общую картину. Приватность реализована не как ограничение
доступа, а как **личный фильтр** поверх общей доски — кнопка «Только мои
задачи» над канбаном скрывает чужие карточки только у вас на экране
(запоминается в браузере), общий прогресс по доске в «рельсе этапов» при
этом всегда показывает картину по всей команде.

### Фоновая синхронизация
Доска и переписка по вопросу сами проверяют изменения раз в 12 секунд —
если коллега подвинул задачу или ответил, увидите это без обновления
страницы. Дополнительно проверка происходит сразу, как только
возвращаетесь на вкладку браузера. Пока открыт диалог редактирования
задачи или идёт перетаскивание карточки — фоновая проверка не
перезаписывает то, что вы делаете.

### Индикатор непросмотренных задач
На карточке доски в списке загорается синяя точка рядом с названием,
если на ней появились задачи с прошлого визита. Точка гаснет сама, как
только открываете доску. Хранится это только у вас в браузере (не общее
для команды поле), поэтому у каждого человека — своя отметка «видел/не видел».

### Мои заметки (`/notes`)
Личный раздел — по образцу популярных заметочников (Apple Notes, Google
Keep): папки слева для группировки по теме, список заметок посередине,
редактор справа с автосохранением по мере набора текста (без кнопки
«Сохранить»). Заметки видны только автору — это проверяется не только в
интерфейсе, но и на сервере: прямой запрос к чужой заметке по её ID
возвращает 404, даже для администратора.

### Приоритет «Горящая» и умная сортировка
- Новый уровень приоритета — **Горящая** (значок пламени, оранжевая полоса слева на карточке).
- Задачи в колонках канбана ранжируются автоматически: сначала горящие,
  затем по сроку сдачи (ближе срок — выше), затем по приоритету.
- Просроченные задачи подсвечиваются красным.

### Комментарий для исполнителя и отчёт о выполнении
- «Комментарий для исполнителя» — инструкция от постановщика, видна прямо
  на карточке без открытия задачи.
- «Отчёт о выполнении» — заполняет исполнитель после выполнения; на
  карточке появляется значок, если отчёт есть.

### Сайдбар «Сегодня» на доске
Справа от канбана — задачи со сроком сегодня и отдельно просроченные.

### Просмотр и редактирование задачи — теперь разные экраны
- При открытии существующей задачи сначала показывается **экран просмотра**:
  название, комментарий для исполнителя, исполнитель, дедлайн, приоритет,
  этап — аккуратно оформлено, без полей ввода.
- Кнопка **«Редактировать»** видна только создателю задачи — открывает
  полную форму редактирования.
- Остальным (например, исполнителю) доступны быстрые действия прямо в
  просмотре — сменить этап и заполнить отчёт о выполнении, без полного
  редактирования задачи.

### Баннер на экране досок
Сверху по центру — баннер (можно заменить своей картинкой, файл
`public/board-banner.png`).

### Одно поле комментария — только для исполнителя
Убрал разделение на «комментарий постановщика» и «отчёт о выполнении» —
осталось одно поле **«Комментарий исполнителя»**, где детали исполнения
пишет только сам исполнитель. Постановщик и остальные участники видят
его как текст, редактировать не могут — проверено не только в
интерфейсе, но и на сервере (прямой запрос от чужого имени отклоняется
с ошибкой 403).

### «Мои задачи» — кнопка на экране досок
Рядом с «Новая доска» — кнопка «Мои задачи», открывает окно со списком
всех задач, назначенных на вас, по **всем** доскам текущего пространства
сразу, с пометкой, с какой именно доски задача. Клик по задаче ведёт на
её доску.

### Мини-игра «Разрезание летящих задач»
Клик по баннеру на экране досок ведёт на `/game` — Fruit-Ninja-стиль игра:
летят доски, зажатой мышью проводите «катаной» — доска красиво
разлетается на осколки, +10 очков. Иногда летит «Отпуск» — его резать
нельзя, штраф −20. 45 секунд на раунд, рекорд сохраняется в браузере.

### Мини-игра — доработано
- Баннер без белой окантовки (обрезка была неточной).
- Экран игры теперь — точная копия главного экрана (шапка, баннер,
  заголовок «Доски задач», кнопки), только без реальных карточек досок —
  это и есть фон, поверх которого летают карточки.
- Летающие карточки — в натуральную величину, как настоящие карточки
  досок, с реальными названиями досок пространства (если они есть).
- Кнопки **паузы**, **рестарта** и **завершения** прямо в игре.
- Полёт заметно медленнее — как в оригинальном Fruit Ninja, а не как
  раньше.

### Доски и задачи
- Редактирование доски (название, описание) и удаление — на странице доски.
- У задач — дедлайн с датой **и временем**.

### Вопросы (`/questions`)
- Личный Q&A-канал: вопрос виден только автору и выбранным получателям
  (можно выбрать одного человека или нескольких) — остальным участникам
  команды не виден.
- Тред ответов, отметка "отвечено / открыт".

### Убран «Вид задачи»
Виды задач (Обычная / Хаммеры / Суперхиты) и связанные с ними поля «Таргет»
и «Найдено, шт.» удалены из продукта — все задачи обычные. Пропали: селектор
вида в форме, бейдж вида и полоса прогресса на карточке, шаг «вид» в диалоге
`/newtask`, отдельное правило прав на редактирование «Найдено».

Колонки `tasks.kind`, `target_count`, `found_count` в базе оставлены как
исторический след и больше не читаются — данные при удалении не пострадали:
на момент правки все задачи были обычными, а таргет/факт не были заполнены
ни у одной.

### Групповые действия с задачами
На карточках появились чекбоксы. Отметьте несколько задач — внизу всплывает
панель: **перенести в этап**, **отправить в архив**, **удалить**. Кнопка
**«Выбрать все»** в панели фильтров отмечает всё, что сейчас видно на доске
(то есть с учётом поиска и фильтров), а чекбокс в заголовке колонки —
задачи только этого этапа; он появляется, когда выделение уже начато, чтобы
не занимать место в заголовке при обычной работе.

Групповое действие выполняется теми же запросами к `/api/tasks/[id]`, что и
одиночное, — пачкой. Отдельного «массового» эндпоинта нет намеренно: в нём
пришлось бы дублировать проверки прав, автолог истории и уведомления.

### Поиск и групповые действия в архиве
В диалоге **Архив** появились строка поиска (по названию, описанию и именам
исполнителей), чекбоксы и «Выбрать все» — чтобы вернуть или удалить сразу
пачку заархивированных задач.

### Несколько исполнителей на задачу
Исполнитель у задачи больше не один. В форме задачи вместо выпадающего списка
— чекбоксы участников пространства, на карточке в канбане показываются
аватары всех назначенных (больше трёх — счётчиком «+N»).

- Задача попадает в «Мои задачи» **каждому** назначенному.
- Уведомление о назначении получает каждый, кого добавили — и только он: при
  правке других полей или снятии одного исполнителя остальных не дёргаем.
- Уведомление о смене этапа уходит всем исполнителям, кроме того, кто менял.
- Фильтр «Все исполнители» на доске показывает задачу, если выбранный человек
  есть среди её исполнителей.
- В боте на шаге выбора исполнителя кнопки работают как переключатели:
  отмечаете нескольких, «Готово» ведёт дальше. Ничего не отметили — задача
  создастся без исполнителя.

Связь хранится отдельной таблицей `task_assignees`. Прежняя колонка
`tasks.assignee_email` осталась историческим следом и больше не читается:
существующие исполнители переносятся в новую таблицу разовой миграцией.

### Архив задач и удаление
У каждой задачи в режиме просмотра появились три действия в одной строке:
**Изменить**, **В архив** и **Удалить**. Раньше удаление было спрятано —
показывалось только после входа в режим редактирования.

- **В архив** — задача пропадает с доски, из «Моих задач» и из списков бота,
  но не теряется: сохраняются история, комментарии и вложения. Обратимо.
- **Удалить** — безвозвратно, поэтому теперь спрашивается подтверждение с
  подсказкой про архив.

Управлять задачей (изменить, архивировать, удалить) может её постановщик —
и **любой администратор**. Иначе задачи ушедшего из команды коллеги, а также
созданные с другого своего аккаунта, оставались бы навсегда без хозяина.

Архив доски открывается кнопкой **Архив** в её шапке: там видно, кто
исполнитель и когда задачу убрали, и по каждой есть **Вернуть** (сразу
появляется на доске, ждать фонового обновления не нужно) и **Удалить**.

### Telegram-бот: создание задач прямо в чате
Команда `/newtask` (или кнопка **➕ Новая задача** в меню бота) собирает
задачу по шагам, без захода в приложение:

- **Пространство и доска** — инлайн-кнопками. Если пространство одно и/или
  доска в нём одна, эти шаги пропускаются автоматически.
- **Текст задачи** — обычным сообщением в чат.
- **Исполнитель** — списком участников пространства, плюс «🙋 На себя» и
  «— Без исполнителя».
- **Срок** — кнопки «Сегодня», «Завтра», «Через 3 дня», «Без срока» и
  **📅 Другая дата**: последняя открывает инлайн-календарь с русскими
  названиями месяцев и днями недели от понедельника, перелистыванием
  месяцев и пометкой сегодняшнего числа. Календарь перерисовывается в том
  же сообщении, а не плодит новые.

После текста бот спрашивает **описание** (шаг можно пропустить) и
**приоритет** — тот же справочник, что и в форме приложения.

Задача создаётся на первом этапе («К выполнению») той же функцией, что и
обычная форма в приложении; исполнителю уходит стандартное уведомление о
назначении с кнопками «В работу / +1 день / Готово». Состояние диалога
живёт в таблице `telegram_drafts` с TTL 30 минут — в памяти процесса его
держать нельзя, на Vercel каждый апдейт бота может обработать свой
экземпляр serverless-функции.

### Архив и удаление задач из бота
В списках `/mytasks`, `/today` и `/assigned` у каждой задачи появилась кнопка
**⚙️** — она открывает карточку задачи прямо в чате: описание, доска, этап,
приоритет, исполнитель и срок. Оттуда задачу можно **переименовать**, **изменить
описание**, **убрать в архив** или **удалить** (удаление переспрашивает — как
и в приложении). Новое название или описание присылается обычным сообщением;
чтобы стереть описание, достаточно отправить «-». Управлять может тот, кто
задачу поставил, или администратор; остальным кнопки не показываются.
Кнопка «← К списку» возвращает ровно ту страницу списка, с которой пришли.

### `/assigned` — что я поручил другим
Обратная сторона `/mytasks`: команда `/assigned` (кнопка **📤 Я поручил**)
показывает задачи, которые вы поставили другим людям. По каждой видно, кому
поручена, на каком этапе, **когда поставлена** и какой срок — просроченные
помечаются, сегодняшние подписаны «сегодня». Список отсортирован по
срочности, длинный листается кнопками «Ещё →» в том же сообщении.

Задачи, которые вы поставили сами себе, сюда не попадают — они и так в
`/mytasks`. Выполненные не засоряют список, их количество показано строкой
в конце.

### Уведомления о смене этапа — и исполнителю тоже
Раньше о смене этапа узнавал только постановщик задачи. Теперь сообщение
приходит и исполнителю, если этап поменял кто-то другой: что за задача,
какой этап был и стал, кто изменил, кнопка «Открыть» на доску. Когда
постановщик и исполнитель — один человек, уведомление приходит одно.
Отключается тем же переключателем «Смена этапа задачи» в настройках бота.

> После обновления выполните `npm run db:migrate` (добавилась таблица
> `telegram_drafts`) и один раз `npm run telegram:webhook` — чтобы
> `/newtask` появилась в списке команд бота в Telegram.

## Быстрый запуск

```bash
npm install
npm run dev
```

## Подключение постоянного хранилища (Postgres)

```bash
# .env.local
DATABASE_URL=postgresql://...ваша строка подключения (Supabase/Neon/Railway)...
SESSION_SECRET=любая-длинная-случайная-строка
```

```bash
npm run db:migrate
npm run dev
```

`SESSION_SECRET` обязателен для прода — без него сессии подписываются
предсказуемым dev-ключом. Сгенерировать случайную строку:
```bash
openssl rand -hex 32
```

## Деплой (Vercel)

```bash
npx vercel --prod
```

В **Vercel → Settings → Environment Variables** добавьте `DATABASE_URL` и
`SESSION_SECRET` для Production (и Preview). Если база физически в другом
регионе (например, Supabase в Сингапуре), `vercel.json` уже закрепляет
серверные функции в `sin1` — при смене региона базы поправьте этот файл.

## Как это устроено внутри

- `lib/session.ts` — подписанные (HMAC) сессионные куки, `getCurrentUser`,
  `requireAdmin`.
- `lib/password.ts` — хэширование паролей (bcryptjs).
- `lib/data.ts` — единая точка входа к данным; переключает между
  `store-memory.ts` (без БД) и `store-db.ts` (Postgres) по `DATABASE_URL`.
- `lib/schema.sql.ts` — DDL: `users`, `allowed_emails`, `boards`,
  `board_members`, `tasks`, `questions`, `question_recipients`,
  `question_messages`.
- `app/api/admin/*` — управление доступами (только role=admin).
- `app/api/questions/*` — приватные вопросы с проверкой участника на
  каждом запросе (автор или получатель, иначе 404).
